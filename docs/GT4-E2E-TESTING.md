# GT4 开发与端到端测试流程

记录日期：2026-11-15。当前验证组合为表端 AirPointer 1.5.3、手机弦月 1.2.29。本文整理电脑自动控制、真机证据和失败恢复的共同规则；[Mac 直连实测](MAC-DIRECT-TEST.md)与[热点持续性经验](WIFI-PERSISTENCE-EXPERIENCE.md)记录具体结果。

## 自动化边界

电脑可执行构建、签名材料校验、已有配对会话恢复、安装结果读取、握手、校准状态轮询、指令 ACK 检查、传感器计数、帧接收、桌面回执和停止。所有步骤须记录已完成、失败或待用户操作。

当前不能可靠从退出状态冷启动表端应用，也不能替用户完成腕部物理动作、保持静止、首次授权和人工加入热点。手机需前台，Mac 首次取当前会话密钥仍依赖 USB/Frida。因而这是具备自动观测和控制的真机测试流程，尚非全套无人工系统。

不动手表的自动输出检查可发送明确标记 synthetic-watch-test 的单帧，并核对真实桌面位移。合成测试不得计入 real-sensor 数量，不得称真实腕动验收。真实腕动的用户确认须独立记录。

公开 examples/gt4-airpointer/ 仅为已授权发布的 1.2.6 BLE 快照；本文当前网络开发版本、手机工程和测试入口位于忽略的 app/，没有随文档发布。公开仓库可复现的构建和安装入口以 README 为准。

## 分阶段执行与验收

| 阶段 | 操作 | 必须保留的证据 |
| --- | --- | --- |
| 环境 | 核对版本、配对、设备目标和现存进程 | 当前版本、连接状态、进程所有权；不保存设备身份或凭据 |
| 构建签名 | 工作区工具构建，检查 Profile、包名、公钥、摘要 | 构建结果和实际校验结果；编译不等于安装 |
| 安装 | 仅执行已授权的目标应用安装/升级 | 文件有效性 1、最终安装 102、列表读回准确版本；传输 100% 不够 |
| 手机恢复 | 恢复已有连接，必要时打开现有应用 | paired、channelReady、writer 实际就绪；不重新配对或清数据 |
| 表端就绪 | 有界 ping、读取应用 ready、hello/status | 原生 202 与应用 ready 分开；相同 boot/session/id 的应用 ACK |
| 网络 | 手机开热点并续期，Mac 加入，等 DHCP 和网关路由 | Mac 持有 2000/2001 套接字；协议 ACK 与应用 ACK 分开 |
| 校准 | calibrate 后轮询，手表保持静止 | ready=true 且 calibration=Ready；请求已接受不够 |
| 输入启用 | 显式 enable 后 arm，再 pointer | 两步各自应用 ACK；短租约持续有效 |
| 指针 | 分别统计来源与转交，读取桌面回执 | real-sensor、synthetic-watch-test 分列；接收/转交/丢弃数、非零位移、用户确认 |
| 停止 | pause、停止管理器、释放适配器和本次服务 | 暂停 ACK、armed=false、停止后的计数与进程/端口复查 |

每阶段设置期限，失败记录所属阶段及最后真实状态。不能将底层写入成功、协议 ACK、应用 ACK、桌面输入混作同一层成功。boot 改变后撤销旧握手，旧会话 ACK 不参与新会话判定；重连后重新握手和校准，不沿用旧 armed 状态。

## 当前工作区的操作顺序

1. 核对已安装版本、已有配对和当前进程。保留现有系统服务；避免重复 manager、端口转发或续期任务。
2. 手机打开弦月并保持前台，开启手表热点；打开表端应用。Mac 人工加入该热点。USB 用于首次会话密钥读取，不能描述为纯 Wi-Fi 无 USB。
3. 在工作区执行本地 test-mac.sh 预览。它等待 DHCP/路由，启动管理会话，校准并轮询 Ready，然后开启预览指针流；默认不发桌面输入。
4. 停止预览，再显式以 --enable 启动。顺序为校准 Ready → arm 应用 ACK → pointer 应用 ACK。用户在安全范围做腕部动作；电脑持续记录真实来源帧和桌面回执。
5. 如需自动链路对照，单独发送合成测试帧并核对光标前后坐标。记录合成来源，避免与腕动结果合并。
6. Ctrl-C 后检查 pause、停止及清理结果。Mac 停止不负责关闭热点；由手机关闭后另查实际无线状态。网络不通时不能伪造暂停 ACK，应记录未确认并检查桌面输入已停。

本地状态与事件位于 app/GT4AirPointer/build/managed/。密码、密钥只允许在内存或匿名管道传递；汇总公开结果前去除地址、设备身份、会话标识和认证材料。所有依赖、缓存、临时文件、SSH known_hosts 与日志留在工作区，不设置 HOME，不在手机落地调试脚本、安装包或日志。

## 恢复、清理和失败经验

| 现象 | 已知结论与处理边界 |
| --- | --- |
| ping 返回 201 或无应用 ready | 冷启动仍不可靠，标记待用户打开表端应用；不能仅凭曾经 201→202 宣称稳定唤起 |
| 校准接受但不 Ready | 尚未校准成功，不 arm；取真实传感器计数、向量及状态 |
| pointer 后 arm 超时 | 当前改为 Ready→arm ACK→pointer ACK；不靠反复重发掩盖顺序问题 |
| 关联 Wi-Fi 后 TCP 失败 | 等 DHCP 和实际网关路由；关联成功不能当网络业务成功 |
| Mac 返回日常 Wi-Fi | 本次会话恢复失败，保留失败尾部与此前有效帧；长稳标失败/未通过 |
| 手机后台掉网 | 普通后台约 60 秒问题未解决，暂用前台；20 秒续期不等于后台可靠 |
| stop 后表端无法重开 | 普通停止用 pause 保留应用；exit ACK 不证明退出完成或可再次冷启动 |
| iPhone 全局触屏无效 | 已确认一次 SpringBoard 忽略交互状态，原因调用者尚未知；不能归因于热点或 Frida |

触屏异常的已确认记录：硬件触控事件存在，采样未见主线程死锁；UIApplication isIgnoringInteractionEvents=true，default 计数 3。平衡清除这 3 个条目后变为 false/0，未重启，用户确认立即恢复。此为当次诊断和恢复证据，不是通用修复命令；受控调用栈跟踪尚在进行，禁止据此反推触发者。

清理只终止本次创建且已核对身份的服务和转发，不使用广泛 kill。适配器需释放并 detach，检查手机服务是否残留或被守护进程拉起。热点 action5 写出与实际关闭分别记录；Mac 回日常网络也要实际核对。不得以重置手表、解除配对、重装运动健康或修改签名校验绕过失败。

## 结果记录标准

每轮汇总写明版本、路径（Mac 直连或手机 TCP）、预览/真实输入、真实/合成来源、阶段 ACK、计数、桌面结果、人工确认、持续时间、失败尾部和清理是否确认。当前结论为：Mac 直连真实鼠标链路通过一次；1,400 真实帧零丢弃且用户确认移动；手机 TCP 隔离路径有 1,680 真实帧和单独 4 像素合成验证；完全无人值守、可靠冷启动、无 USB、后台持续连接和长期稳定运行均未完成。

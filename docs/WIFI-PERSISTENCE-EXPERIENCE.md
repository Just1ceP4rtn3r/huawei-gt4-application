# GT4 热点持续性经验

记录日期：2026-11-15。当前手机弦月 1.2.29，表端 AirPointer 1.5.3。当前架构由手机负责热点开启、续期和关闭；Mac 只建立业务 TCP。长时间稳定性未通过，普通后台约 60 秒掉网的问题尚未解决，用户暂用手机应用前台。

## 已确认的协议与实验

手机通过已认证 BLE 会话发送 37/01 SampleConfiguration，配置 ID 900100019（0x35A66FB3），包名 hw.uniedevice.wifiTransfer。action3 开启或续期，action4 查询配置，action5 关闭。action4 可能更新热点密码，不能假定先前凭据始终有效；action5 写入完成不等于已经取得关闭业务确认。

早期测试中原始热点约 45 秒失去链路。持久 iOS 网络配置、双 TCP 连接、断开 BLE、周期应用 status 和完整 P2P ACK 均未解决。单次约 30.5 秒补发 action3 后，约 69.7 秒仍在线、79.97 秒已离网，支持开启请求刷新寿命的假设；未取得匹配配置回复，不能把写入成功称业务确认。

每 20 秒补发 action3 的历史实验在同一 TCP 连接完成 180 秒业务对照：8 次续期请求、58 次业务 ACK、657 个 TCP 包，598 次协议 ACK 写入成功、0 失败，无自动重连。该结果证明这段时间的业务可用性，不能推广为永久热点或完整鼠标验收。

当前手机已接管 20 秒续期。Mac 脚本已移除热点开启、关闭、续期及 --auto-wifi。不要将早期手机内存 agent 的续期机制与当前手机应用实现同时运行。

## 原生路径与未完成事项

原生 SHWiFiLink 在双端口连接后启动无限超时读取并保持手机亮屏，未在该回调发现额外保活。Wi-Fi OTA 包含 09/01 准入、09/02 协商、窗口文件数据和结束流程；09/0A 涉及状态切换及断开 BLE。尚未证明缺少 OTA 状态导致热点回收，也未发现可设置 AP 时长的字段。不得以 OTA 请求或假文件数据替代保活。

官方运动健康曾正常重新连接，但未完成官方长时间 Wi-Fi 传输对照。20 秒 action3 是实测兼容策略，不能称为华为官方永久热点机制。系统明文模式请求返回 100010 拒绝；不能因本地构帧可用就宣称设备接受明文或绕过认证。

仍需验证：手机前台的更长连续运行、普通后台约 60 秒掉网原因、Mac 切回日常网络的触发条件及恢复、停止后无继续续期、异常中断后的状态收敛。最新 Mac 测试虽收到 1,400 个真实帧并经用户确认鼠标移动，随后仍切回日常 Wi-Fi；长稳不能标记完成。

## 历史实现与清理经验

早期本地 relay/ap-renewal.js 使用会话代次校验及串行写队列，停止后排队续期不得继续写出，lost/release/认证失效时取消。离线测试覆盖间隔、取消、失效和迟到操作；这些不代表设备耐久通过。该实现位于忽略的 app/，不在公开源码快照内。

历史暂停时 manager 返回 stopped、armed=false、enabled=false；exit 取得 ACK，但未确认表端进程退出。热点关闭只有写入证据。当前 Mac 日常停止使用 pause，热点关闭由手机执行，必须按当前职责检查清理，不能照搬旧退出逻辑。

原始本地证据位于 artifacts/gt4-network-runtime/ 的 tcp-renewal-business.json、tcp-manager-renewal-validation.json、tcp-ap-single-renewal.json 和 ap-native-flow/。证据含环境信息，不提交原文件；公开文档只记录可核对的结果与限制。

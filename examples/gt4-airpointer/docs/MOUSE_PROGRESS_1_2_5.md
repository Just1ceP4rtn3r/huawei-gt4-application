# 1.2.5 鼠标功能实测状态

目标仅为手表控制 Mac 鼠标。自动化管理不能代替鼠标真机验收。

## 已有证据

- 1.2.2 真机状态确认加速度采用 g 单位，归一化后远程校准返回 Ready。
- 原生 sendMsg 仍约 3012ms 后以零参数失败，不能把映射后的 206 当作更详细的原生错误。
- 应用运行时，下行指令和通过 detect 路由分段回传的应用日志、状态已经验证。
- 1.2.3 引入紧凑指针探测消息。编码/解码离线通过，但没有真实指针帧或实际鼠标运动证据。
- 临时通过 NSArgumentDomain 在手机内存切换 nativeIOS 声明、使用保存密钥重连后，启动仍连续返回 201。原内存配置已恢复；未写入手机配置文件。该结果不证明手机声明是根因，也不排除其他能力协商差异。
- 参照 Gadgetbridge 的 ping 路由，仅将 ping 来源改为 com.huawei.health，对照仍返回 201；下发原应用身份的数据探测返回 206。未修改签名验证或配对信息。
- 1.2.4 和 1.2.5 均获得安装 102 和应用列表版本读回确认。安装成功不代表应用运行成功。

## 内存问题及修改

对 1.2.3 实际编译产物使用 SDK Jerry 执行 onInit/onShow（原生 API 以离线 stub 代替）复现 ERR_OUT_OF_MEMORY，测试引擎堆大小 49144 字节。此前 parse-only 和 Node 执行测试未覆盖这个问题。

1.2.5 移除设置/本地日志/预览页面和旧 gt4log 导出队列，保留必要鼠标按钮；校准以计数、向量和、平方和计算偏差与方差，不再保留样本对象数组。control.js 从 1.2.3 的 35715 字节减少至 29280 字节。

新增 tests/jerry_runtime_test.py，执行实际编译产物初始化、渲染、40 组模拟静止传感器回调和校准断言。1.2.5 返回 OFFLINE_JERRY_RUNTIME_READY；堆峰值 49144/49144，仍需关注内存余量。这个数字包含 JavaScript mock 开销，不能当作真机内存测量，也不能据此宣称实际黑屏根因已完全确定。

管理器修复了持续收到合法指针却因缺少分段管理事件而误判断连的问题；新鲜且递增的合法指针可更新活跃时间，重放/过期帧不能续命。37 项管理器离线测试通过。

## 当前未通过项

自动启动仍缺少应用 ready；真实指针输入、点击、拖动、滚动以及持续控制体验尚未通过真机验收。接收器已经支持明确的 enable 模式，等待应用运行后先测来自手表的标记合成位移及 Mac 坐标回执，再校准并启用真实传感器流。合成位移仅验证传输和桌面输入，不等于真实手腕控制。

证据位于工作区 .local/logs/gt4airpointer-*-1.2.5.*、.local/logs/gt4airpointer-ping-route-comparison.log 和 examples/gt4-airpointer/build/managed/events.ndjson。运行期进程状态会变化，以当前管理器状态与进程检查为准。

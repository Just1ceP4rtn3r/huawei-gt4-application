# 输入协议与控制状态

## 通道

- 手表侧：Lite Wear Engine `sendMsg`，ASCII JSON，表端主动限制在 900 字符以内；接收器额外设定 4096 字节拒绝上限。
- 蓝牙侧：现有配对加密会话，SID `0x34`、CID `0x01`。只处理表端包 `com.example.gt4counter` 与本地路由 `local.gt4bridge.crescent`（兼容历史 `local.gt4airpointer.relay`）之间的消息。
- 表端来源身份必须匹配 `包名 + "_" + Base64(开发者证书的未压缩 EC 公钥点)`，不是证书 SHA-256。适配器从根现有 CSR 与证书链找到匹配叶子，不直接把链中的第一个证书当成应用证书。
- 手机应答 P2P 传输接收码 207，手机侧 ping 应答码 205（手表侧应答为 202）；这只说明接收路由应答，不代表传感器有效或 Mac 已执行鼠标动作。
- 手机到 Mac：Frida 客户端回调，转入有界队列，再经本地子进程 stdin 管道发送。没有新增 LAN 控制端口。
- Mac 状态：relay 在子进程存活且最近 500ms 收到相同会话的接收器回执时每秒回传 `relay` 消息。`enabled` 表示进程以启用模式运行且启动时具备事件权限，不是独立测量的鼠标位移回执。

## 指针帧 v1

```json
{
  "v": 1,
  "t": "pointer",
  "session": "1794582000000-123456",
  "seq": 42,
  "sent": 1794582001000,
  "armed": true,
  "dx": 4.25,
  "dy": -1.5,
  "scroll": 0,
  "buttons": [{"id": 3, "kind": "left", "age": 20}]
}
```

| 字段 | 含义 |
| --- | --- |
| `session` | 本次 Connect 生成的标识，使用数字和连字符，不是设备 UDID |
| `seq` | 本次会话严格递增序号；重复、逆序忽略 |
| `sent` | 手表构造发送帧时的毫秒时间；Mac 估计相对时钟偏移来识别额外传输积压，不要求两端系统时钟相同 |
| `armed` | 用户已校准并 Resume，且传感器数据未超时；false 会释放按键 |
| `dx/dy` | 相对屏幕坐标，X 向右、Y 向下；每帧上限 ±100 |
| `scroll` | 像素滚动量，每帧上限 ±60；正负方向可通过配置调整 |
| `buttons` | 最多 8 个带 ID 的动作；kind 为 left/right/double/drag，age 为动作生成以来的毫秒数 |

表端重复携带最近 700ms 内的按钮动作，以便有界丢帧时仍有机会送达；Mac 只接受估计总年龄不超过 350ms 且未处理的 ID。相对位移不重放，丢帧可能损失一小段移动。这是避免失联后突然补发运动和点击的取舍，不保证在所有无线丢包条件下不丢输入。

## 超时与状态

1. 每个 native send 同时仅一个在途帧，一个待发送帧；待发送帧被最新运动替代。5000ms 发送未完成则停止该 sender，需要重新 Connect，不并发重试卡住的 native 请求。
2. 手表每 50ms 汇总运动，传感器采用 game 请求档位；真实回调频率取决于设备。超过 250ms 无选定传感器回调，立即暂停并清空动作。
3. relay 接收队列最多 4 帧，队列等待超过 200ms 的帧丢弃；iPhone 应答帧队列也设置预算。
4. Mac 以最小观测时钟偏移估计额外延迟。超过 250ms 积压则释放拖拽；重复序号和最近退休会话拒绝。
5. Mac 每 100ms 检查一次看门狗，500ms 无有效帧则释放拖拽，恢复数据后按新的 armed 帧处理。
6. 页面隐藏时退订两个传感器、停止桥接、恢复亮屏并保持暂停；最后 pause 消息可能因断线未送达，Mac 看门狗作为独立保护。

## 1.1.7 实验诊断通道

原生 `sendMsg` 失败时，官方 JS SDK 会把原生原因统一转换为 206。`common/native-wearengine.js` 在转换之前记录回调，最多保存 24 条内存记录，包含序号、相对时间、操作/回调名称、参数个数与受限参数摘要。配置调用不保存包指纹或证书，接收回调只记录消息长度；不记录健康数据、传感器样本或配对密钥。

首次发送失败后 sender 关闭，不再循环发送运动帧。诊断导出从内存环选取最近记录，限制 JSON 总长 960 ASCII 字符。将每 48 字符转为十六进制，逐次调用原生 `detect`，目标名为：

```text
local.gt4bridge.crescent.gt4log.s<8位临时token>.p<分段号>n<总段数>.x<hex>
```

这利用此前实测能到达手机的 kind=1 探测报文，避免依赖失败的 kind=2 应用数据发送；它是自定义诊断实验，不是华为标准日志导出接口。若固件限制目标名或探测也失败，导出同样不能完成。每次 Connect 最多导出一次、20 段，每段等 ACK 最多 2 秒、间隔 150ms，第一段失败就停止。页面退出会取消后续段。导出不调用 setPackageName/setFingerprint；重新 Connect 会重建正常路由。

手机在现有已配对会话内仅接受源包名正确、命名格式和长度符合限制的诊断 ping，按实际目标反转 ACK205。ping 不携带数据消息的公钥身份字段，因此该实验日志不等同于经过数据帧身份校验的输入。诊断事件独立于 pointer 分发，绝不送往鼠标接收器。

手机只在内存中解析并经 Frida 返回电脑，不创建日志或其他文件。电脑 `relay/watch_logs.py` 最多重组一个 960 字符快照，重复段忽略；只有完整且结构有效的 JSON 才追加到 `build/watch-diagnostics.ndjson`。收不到完整快照不得宣称已取得手表日志。`Options → Local diagnostic log` 可逐条查看内存记录，作为传输失败时的回退；退出应用后内存记录不保证保留。

显示 `Log BLE submitted` 只代表 detect 回调成功，完整快照在电脑落盘才是日志到达的证据。诊断代码只观测本应用调用及其原生回调，不能读取 GT4 系统内核或其他应用日志。

2026-11-14 本机GT4的1.1.7已完成一次10段快照回传，电脑完整重组成功。结果在 `build/watch-diagnostics.ndjson`，时间线解释在 `ACCEPTANCE.md`；该成功只覆盖本应用日志的自定义ping传输，不覆盖正常sendMsg指针数据发送。

## 算法和待标定参数

陀螺仪默认按 rad/s，yaw=z、pitch=x、默认反向映射；加速度按 m/s²。先对静止样本求角速度偏置并检查方差和重力幅值，再以死区和低通滤波生成相对速度。加速度倾斜模式使用重力方向相对校准姿态的角度差，不能获得 6DoF 空间位置。

双敲是两个间隔 140–420ms 的加速度冲击并限制陀螺仪幅值，默认关闭。手腕佩戴、外壳、采样率差异会改变波形，离线合成测试不能替代真人误触率验证。方向、单位、灵敏度、采样率、延迟和敲击阈值都列入真机验收。
